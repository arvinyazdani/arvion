# سیستم طراحی آرویون

این سند مرجع اجرای رابط عمومی، حساب مشتری، فرم‌های نیازسنجی و مرکز مدیریت است. هر جزء جدید باید از tokenهای `core/static/core/css/tokens.css` استفاده کند و در حالت روشن، تیره، فارسی و انگلیسی بررسی شود.

## اصول

- متن و سطح از هم مستقل‌اند؛ برای پس‌زمینه از `--color-surface` و برای متن از `--color-ink` استفاده می‌شود.
- پنل تیرهٔ برند همیشه `--color-panel-dark` با متن سفید واقعی دارد و با تغییر theme وارونه نمی‌شود.
- رنگ وضعیت فقط برای انتقال معنی استفاده نمی‌شود؛ عنوان یا آیکن/متن وضعیت نیز لازم است.
- تمام فاصله‌ها، شعاع‌ها، سایه‌ها و رنگ‌های مشترک باید token باشند.
- در RTL فقط propertyهای منطقی مانند `margin-inline-start` و `inset-inline-end` استفاده می‌شوند.

## Tokenها

| گروه | Tokenهای اصلی | کاربرد |
|---|---|---|
| برند | `--color-brand-orange`, `--color-brand-orange-text`, `--color-mint` | CTA، تأکید و هویت برند |
| متن | `--color-ink`, `--color-muted` | متن اصلی و توضیح ثانویه |
| سطح | `--color-paper`, `--color-surface`, `--color-surface-2` | بدنه، کارت و سطح فرعی |
| پنل ثابت | `--color-panel-dark`, `--color-panel-dark-2` | hero و نوار مدیریت |
| وضعیت | `--color-*-surface`, `--color-*-text` | موفق، هشدار، خطا و اطلاعات |
| مرز | `--color-line` | border و جداکننده |
| فاصله | `--space-1` تا `--space-10` | فاصله‌های تکرارشونده |
| شعاع | `--radius-sm`, `--radius-md`, `--radius-lg`, `--radius-pill` | کنترل، کارت و pill |
| سایه | `--shadow-sm`, `--shadow-md` | ارتفاع سطح |

## اجزای پایه

### دکمه

- Primary: یک اقدام اصلی در هر ناحیه؛ حداقل ارتفاع ۴۴ پیکسل.
- Secondary: اقدام پشتیبان با سطح شفاف و مرز قابل‌دیدن.
- Ghost: اقدام کم‌اهمیت مثل «بعداً» یا «انصراف».
- Disabled: علاوه بر کاهش opacity، cursor و رفتار کلیک غیرفعال می‌شود.
- Loading: متن وضعیت نزدیک دکمه با `role="status"` نمایش داده می‌شود و دکمه تا پایان درخواست غیرفعال است.

### فیلد فرم

- label مرئی و متصل به کنترل الزامی است.
- help text با رنگ muted و error با token خطا نمایش داده می‌شود.
- focus با outline نارنجی سه پیکسلی دیده می‌شود؛ حذف outline ممنوع است.
- placeholder جای label را نمی‌گیرد.
- اطلاعات حساس در `localStorage` ذخیره نمی‌شوند.

### کارت و Badge

- کارت روی `--color-surface` و border روی `--color-line` است.
- Badge باید هم متن وضعیت و هم رنگ semantic داشته باشد.
- رنگ‌های ثابت روشن در کارت یا badge ممنوع‌اند، چون Dark Mode را می‌شکنند.

### Wizard

- فقط یک مرحله در هر لحظه قابل مشاهده است.
- «ادامه» مرحلهٔ جاری را پیش از حرکت اعتبارسنجی می‌کند.
- Enter در input معادل ادامه است و فرم ناقص را submit نمی‌کند.
- Back/Forward مرورگر باید مرحله را حفظ کند.
- خطای سرور یا شبکه پاسخ کاربر را حذف نمی‌کند.
- رضایت پیش‌نویس برای هر فرم جداگانه است و فقط فیلدهای allowlistشده ذخیره می‌شوند.

### Dialog و منوی موبایل

- هنگام بازشدن، focus وارد لایه می‌شود و با Escape بسته می‌شود.
- Tab داخل لایه محصور می‌ماند و پس از بستن به trigger برمی‌گردد.
- پس‌زمینه برای screen reader و تعامل ناخواسته قابل دسترسی نیست.

## معیار دسترس‌پذیری

- کنتراست متن عادی حداقل ۴.۵:۱ و متن بزرگ/کنترل حداقل ۳:۱.
- محدوده لمس کنترل‌ها حداقل ۴۴×۴۴ پیکسل.
- تمام عملیات با کیبورد قابل انجام‌اند.
- focus همیشه قابل‌دیدن است.
- خطاها با `role="alert"` و پیام عملیاتی اعلام می‌شوند.
- animation در `prefers-reduced-motion: reduce` متوقف یا بسیار کوتاه می‌شود.
- در zoom دویست درصد، اسکرول افقی در viewport اصلی ایجاد نمی‌شود.

## کنترل پیش از ادغام تغییر UI

1. صفحه در عرض‌های ۳۶۰، ۳۹۰، ۷۶۸، ۱۳۶۶ و ۱۹۲۰ بررسی شود.
2. Light و Dark، فارسی و انگلیسی جداگانه بررسی شوند.
3. Tab، Shift+Tab، Enter و Escape آزمایش شوند.
4. حالت‌های empty، loading، error، success و disabled دیده شوند.
5. متن، دکمه یا جدول از viewport خارج نشود.
6. `prefers-reduced-motion` و zoom دویست درصد بررسی شوند.
7. هیچ رنگ یا spacing مشترک جدیدی بدون token اضافه نشود.
