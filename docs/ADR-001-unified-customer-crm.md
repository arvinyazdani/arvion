# ADR-001: CRM واحد روی داده‌های دامنه موجود

**وضعیت:** پذیرفته‌شده  
**تاریخ:** 2026-08-15  
**تصمیم‌گیرنده:** مدیریت آرویون

## زمینه

درخواست همکاری، نیازسنجی CRM و کلینیک، فرم تخصصی و قرارداد در مدل‌های مستقل و دارای داده واقعی نگهداری می‌شوند. انتقال یا ادغام فیزیکی این رکوردها ریسک از دست‌رفتن سند، شکستن لینک عمومی و دشوارشدن Audit را ایجاد می‌کند.

## تصمیم

`CustomerCase` لایه عملیاتی واحد است و با ContentType/Object ID به منبع اصلی متصل می‌شود. `CaseDocument` snapshot و checksum سند، `CaseActivity` Timeline و `CaseTask` کار مسئول‌دار را نگهداری می‌کنند. رکوردهای دامنه منبع حقیقت باقی می‌مانند.

## گزینه‌های بررسی‌شده

### انتقال همه داده‌ها به یک مدل بزرگ

- پیچیدگی اولیه متوسط؛ ریسک مهاجرت و از دست‌رفتن سازگاری زیاد.
- Query ساده‌تر، ولی مدل بسیار شکننده و پر از ستون‌های نامرتبط می‌شود.

### لایه پرونده روی مدل‌های موجود — انتخاب‌شده

- مهاجرت غیرمخرب و امکان بازگشت ساده.
- نیازمند همگام‌سازی Signal و کنترل سازگاری است.
- برای اندازه فعلی PostgreSQL و تیم Django کم‌هزینه‌ترین راه قابل نگهداری است.

## پیامدها

- همه مشتری‌ها یک مسیر عملیاتی و Timeline مشترک دارند.
- اسناد اصلی حذف یا جابه‌جا نمی‌شوند.
- ساخت منبع جدید باید به سرویس sync پرونده متصل شود.
- در مقیاس بسیار بزرگ، Generic Relation و فهرست ۲۰۰تایی باید با API صفحه‌بندی‌شده و ایندکس‌های جست‌وجو جایگزین شود.

## جریان داده

`Lead / CRM / Clinic → Signal → CustomerCase → Task + Activity + Document → Notification → Push/SMS`

`Specialist Form / Contract → CaseDocument snapshot + checksum → Timeline`
